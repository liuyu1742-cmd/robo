# 固定标准指令动作解析验收设计

## 目标

建立可由第三方复核的正式动作解析验收集，用以检验系统是否能将项目范围内的固定标准指令及常见同义表达，解析为预先规定的标准动作序列。

该验收针对“固定范围的指令映射正确性”，不声明对无限开放表达的泛化能力。

## 验收范围

当前目录共有 138 条任务—物体操作关系。每条关系包含：

1. 1 条标准指令；
2. 3 条固定的常见同义/口语指令；
3. 1 条对应的标准动作序列。

因此正式验收集共有 552 条测试用例。四种表达属于不同测试用例，但同一关系的预期动作序列完全相同。

例如，“帮我倒杯水”“给我倒水”“我想喝水”“倒点水过来”可以是四条固定测试项，均要求输出同一倒水动作序列。

## 数据与隔离

正式验收文本由独立的“official acceptance”模板族生成，不能与下列数据发生指令哈希重合：

- 增强训练集；
- 增强开发集；
- 助手生成自测集；
- 已锁定人工终测的哈希清单。

正式验收集生成后冻结，保存完整测试集、输入/答案哈希及模型哈希。后续若改动模型、指令或动作标准，必须建立新版本验收集，不能覆盖本次报告。

## 评分规则

测试程序逐条执行以下过程：

1. 输入一条固定验收指令；
2. 系统生成关系预测和原始动作序列；
3. 在记录原始输出后，可额外记录约束后动作序列；
4. 将原始动作序列与该条预设标准动作序列逐项比较。

只有动作名称、参数和顺序都完全相同，才记为通过。

原始整序列准确率 = 原始动作完全通过条数 / 552。

90% 门槛为至少 497 条通过（552 × 90% = 496.8，向上取整）。

## 对外证据

正式报告必须包含：

- 测试总数、通过数、原始整序列准确率和是否达到 90%；  
- 关系识别准确率、约束后准确率及低置信度条目；  
- 固定验收集、模型、目录和报告的 SHA-256；  
- 每条用例的指令、预期动作、原始输出和通过状态；  
- 明确的范围说明：结果证明固定验收范围内的映射准确性，不等同于所有任意中文表达都达到该准确率。

## 不做的事

- 不使用、修改或重跑已锁定的 414 条人工终测；
- 不将正式验收答案加入训练或开发数据；
- 不把助手生成自测的成绩作为正式验收成绩。
