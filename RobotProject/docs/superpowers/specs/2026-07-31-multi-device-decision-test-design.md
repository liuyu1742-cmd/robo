# 多设备协同决策与文档测试设计

## 目标

为现有自然语言指令入口增加一个独立的多设备协同场景，并按照参考文档 `3.docx` 的测试过程和合格判定完成可复现测试。测试完成后生成更新版 DOCX，不覆盖用户桌面的原始文件。

## 实现范围

- 新增就寝环境协同指令：
  - `准备就寝环境：空调设为24℃、关闭电动窗帘、将卧室灯调至低亮度，并检查各设备状态。`
- 协同设备只使用项目目录中已经登记的对象：
  - `air_conditioner`
  - `electric_curtain`
  - `bedroom_lamp`
- 不新增项目中不存在的加湿器，不宣称已经驱动真实家电。
- 输出内容包括：
  - 场景及设备识别；
  - 每台设备的有序动作；
  - 可并行执行分组；
  - 同一设备互斥动作检查；
  - 设备状态确认；
  - 环境温度变化后的重新规划信息。

## 接口设计

新增 `tools/multi_device_coordination.py`：

- `is_multi_device_instruction(text)`：识别支持的就寝协同指令。
- `plan_multi_device_instruction(text, environment=None)`：生成结构化协同方案。
- `format_multi_device_result(result)`：生成面向用户的中文真实输出。

`manual_instruction_test.run_instruction` 在单任务解析前识别多设备指令；匹配成功时返回协同结果并写入原有 JSON 报告路径。普通指令保持现有行为。

## 协同策略

1. 校验空调、电动窗帘和卧室灯均在项目设备目录中。
2. 第一执行组并行完成设备定位与状态检查。
3. 第二执行组并行完成：
   - 空调开启、模式选择、目标温度设为 24℃；
   - 电动窗帘关闭；
   - 卧室灯亮度设为 20%。
4. 第三执行组检查三台设备最终状态。
5. 对每台设备执行冲突检查，禁止同一方案同时出现开/关、开帘/关帘等互斥目标。
6. 当输入环境温度低于 20℃或高于 28℃时标记为重新规划，并分别选择制热或制冷模式；其余情况选择自动模式。

## 测试设计

- 使用固定随机种子 `20260731`，从已审核的 VLA 82 任务—物体模板中随机抽取
  两个属于不同 VLA 任务的物体。
- 加入一个多设备协同综合任务，共三个测试用例。
- 每个用例执行 10 次，使用 `time.perf_counter_ns()` 记录从接收指令到完整结构化方案输出完成的耗时。
- 多设备用例额外注入一次临时温度变化，记录重新规划耗时及输出。
- 原始测试记录保存为 JSON，包含 10 次单次耗时、平均耗时、真实输出、通过状态和运行环境。
- 每轮测试另存独立 JSON 证据，记录墙钟起止时间、`perf_counter_ns` 起止值、
  纳秒差值、换算秒数和完整输出 SHA-256。

## 合格判定

- 单任务平均决策耗时不超过 3 秒。
- 多设备协同综合任务平均决策耗时不超过 5 秒。
- 环境临时变化后的重新规划耗时不超过 5 秒。
- 除耗时外，输出必须包含预期任务/设备、非空动作计划；协同方案必须通过冲突检查。
