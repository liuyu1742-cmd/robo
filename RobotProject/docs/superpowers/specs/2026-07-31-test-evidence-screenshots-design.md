# 测试证据截图与实验结果解释设计

## 目标

在现有测试报告中增加便于审核者查看的真实测试截图，并为每张图片和实验结果补充解释。截图只能读取已经通过 SHA-256 校验的本次测试 JSON，不允许手工填写或修改耗时数据。

## 证据层级

报告同时保留三层证据：

1. 原始证据：31 份逐轮 JSON，包含墙钟时间、`perf_counter_ns` 起止值、耗时、完整输出和输出 SHA-256。
2. 可视化页面：从汇总 JSON 和逐轮 JSON 自动生成的本地只读 HTML。
3. 报告截图：使用浏览器对本地可视化页面进行截图，并嵌入 DOCX。

截图用于方便阅读；JSON、原始计时值和 SHA-256 用于复核，截图不替代原始证据。

## 截图组成

生成并嵌入以下六张 PNG：

1. `01_test_overview.png`
   - 测试命令、执行时间、Python/操作系统、随机种子、计时公式；
   - 三个用例、平均耗时、阈值及合格状态。
2. `02_vla_run_evidence.png`
   - 两个随机 VLA 用例各 10 次耗时；
   - VLA 任务、物体、证据 ID 和输出哈希前缀。
3. `03_multi_device_run_evidence.png`
   - 多设备协同 10 次耗时；
   - 环境变化重规划耗时；
   - 每轮原始纳秒差值和证据 ID。
4. `04_multi_device_subtasks.png`
   - 空调、电动窗帘、卧室灯三个既有动作解析子任务；
   - 每个子任务的任务类别、对象、操作及基础动作；
   - 协调后的 24℃、关闭窗帘、20% 亮度目标和冲突检查结果。
5. `05_timing_chart.png`
   - 三个用例 10 次耗时曲线；
   - 平均值和 3 秒/5 秒合格线；
   - 图中明确标注多设备耗时较高是因为实际调用三个既有解析子任务。
6. `06_timing_code_and_output.png`
   - 自动读取项目中实际执行的 `perf_counter_ns` 计时代码并显示源代码行号；
   - 对照展示 DEC-003 第 10 轮原始计数器值、耗时、输出 SHA-256 和三个子任务输出；
   - 用于证明报告中的耗时来自真实代码执行及对应证据 JSON，而非人工填写。

## 报告结构

在现有 `3.2.6.5 测试证据` 后新增：

`3.2.6.6 图像化测试证据与结果解释`

每张图片按以下结构呈现：

- 图题；
- 图片；
- 图片说明：说明图中数据来源、阅读方法和对应证据文件；
- 结果解释：说明该图如何支持耗时、输出完整性或三设备调用的判定。

## 实验结果解释

报告必须明确说明：

- 前两个用例来自不同 VLA 任务与物体；
- `elapsed_seconds=(ended_perf_counter_ns-started_perf_counter_ns)/1,000,000,000`；
- VLA 用例只读取审核后的动作模板和额外细分动作，因此耗时约为毫秒级；
- 多设备用例实际执行三次既有自然语言动作解析，再进行协调、参数补充和冲突检查，因此耗时约为 1.2 秒，明显高于 VLA 模板检索；
- 三个平均耗时及重规划耗时均低于对应阈值；
- 测试是软件决策规划测试，不代表实体家电已经执行。

## 验证

- 截图中的每个数值必须与汇总 JSON 一致。
- 每张 PNG 必须存在、非空且尺寸足以在 DOCX 中清晰阅读。
- DOCX 必须包含 6 张新增图片、对应图题和解释段落。
- 原始用户文档保持不变，继续更新项目 `outputs` 中的副本。
- 若本机仍缺少 Word/LibreOffice，只能对嵌入图片本身进行逐图检查，并对 DOCX 做结构化检查；交付时披露无法逐页渲染 DOCX。
