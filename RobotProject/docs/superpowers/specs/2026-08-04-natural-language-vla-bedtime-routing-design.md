# 自然语言 VLA 与就寝协同指令路由设计

## 目标

让桌面弹窗和命令行入口正确处理以下自然语言指令，并显示“完成情况：通过”：

- `把牙膏放到洗手台的杯中`
- `把数码相机安装到三脚架上`
- `我要睡觉了`

同时支持明确的就寝同义表达，例如“我想睡觉了”“准备睡觉”“该睡觉了”，并避免“我不想睡觉”等否定表达误触发多设备协同。

## 根因

项目已经具备两个 VLA 模板：牙膏对应 `vla_081`，数码相机对应 `vla_046`；模板选择器能够直接识别用户给出的两句话。当前桌面入口却先调用普通的 15 类任务／138 种物体解析器，解析失败后直接退出，因此没有机会进入 VLA 模板选择。

多设备协同入口在普通解析之前执行，但现有触发词仅包含“准备就寝环境”“就寝环境”“睡眠模式”“睡前环境”，不包含“我要睡觉了”等生活化表达。

## 方案选择

采用统一的分层路由顺序：

1. 识别已支持的多设备协同场景；
2. 识别 VLA 任务—物体模板；
3. 未命中以上两类时，再进入原有 15 类任务／138 种物体解析器与模型流程。

不把 VLA 对象并入普通目录，因为两套任务的标识、动作模板及审核数据来源不同。也不只硬编码三条完整句子，因为那样无法合理支持用户已确认的同义表达。

## 组件与数据流

### VLA 指令规划器

新增一个职责单一的共享模块，接收自然语言文本并调用现有 `select_vla_action_template`。命中后读取已审核的额外细分动作序列，返回统一的 `vla_task_decision` 结果，包括：

- VLA 任务 ID、物体 ID 和中文物体名；
- 原始操作标签；
- 基础动作模板；
- 额外细分动作序列；
- `completed=True` 和 `completion_status=通过`。

桌面入口与测试报告基准入口共同调用该模块，避免两处复制 VLA 规划逻辑。

### 桌面／命令行入口

`run_instruction` 按“多设备 → VLA → 普通解析”的顺序路由。VLA 结果直接写入现有 JSON 报告并交给统一格式化函数显示，不加载普通语义模型；普通任务路径保持现状。

### 就寝场景识别

扩展肯定触发短语，覆盖：

- 我要睡觉了；
- 我想睡觉了；
- 准备睡觉；
- 该睡觉了；
- 现有的就寝环境与睡眠模式表达。

在肯定匹配前检查局部否定表达，如“不想睡觉”“不睡觉”“不用准备睡觉环境”“不要进入睡眠模式”。命中否定表达时不进入多设备协同，后续仍按普通路由处理。

## 输出行为

牙膏指令应识别为 `bathroom_personal_care / vla_081`，输出“放入洗手台上的杯中”的基础模板和对应审核后的细分动作。

数码相机指令应识别为 `indoor_installation / vla_046`，输出“数码相机安装到卧室三脚架”的基础模板和对应审核后的细分动作。

肯定就寝指令应生成现有多设备方案，实际调用：

- `appliance_management / air_conditioner / turn_on`；
- `appliance_management / electric_curtain / close`；
- `bedroom_service / bedroom_lamp / turn_on`。

协调目标仍为：空调 24℃、关闭电动窗帘、卧室灯 20% 亮度，并执行冲突检查。

## 错误处理

- VLA 模板存在但缺少审核后的细分动作时，保留明确错误，不伪造输出；
- 否定睡眠表达不得触发三设备动作；
- 未匹配多设备、VLA 或普通任务的文本继续返回当前“未能在15类任务/138种物体中匹配”的错误；
- 不改变普通任务的模型生成、约束和合格判定逻辑。

## 测试与验收

先编写失败测试并确认失败原因与当前问题一致，再实施最小修改。

验收条件：

1. 三张截图中的原句通过 `manual_instruction_test.run_instruction` 后均为 `completed=True`；
2. 格式化文本均包含“完成情况：通过”；
3. 两条 VLA 指令分别匹配 `vla_081` 和 `vla_046`，且包含非空细分动作序列；
4. 已确认的四种就寝表达均触发三设备协同；
5. 否定表达不触发多设备协同；
6. 现有 VLA、普通解析、多设备协调、运行时和 CLI 回归测试全部通过。

## 范围边界

本次只修改自然语言路由与结果展示，不修改已审核的 VLA 表格内容、动作序列、模型权重、多设备目标参数或测试报告历史证据。
