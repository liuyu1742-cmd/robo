# 全物体多设备协调联动表设计

## 目标

为当前项目中的原有物体和 VLA 对象设计可审核的多设备／多物体协调联动命令，并生成 Excel 表格供用户审核。每个对象至少参与一条具有真实生活逻辑的联动命令，同时为每个对象提供独立的细分动作解析。

本阶段只生成审核表，不修改项目运行代码。用户审核和修改表格后，再决定是否把联动场景写入协调器。

## 覆盖口径

项目文档称原有 120 种物体，但当前 `meta/compliance_catalog_15x120.json` 实际包含：

- 15 类任务；
- 138 个任务—物体归属关系；
- 123 个唯一原有物体；
- 部分物体跨多个任务重复出现。

VLA 目录包含 82 个独立对象 ID。表格按当前代码真实范围审核：

- 原有唯一物体：123 个；
- VLA 对象：82 个；
- 合计审核对象：205 个。

同一实体如果同时存在于原有目录和 VLA 目录，仍按各自 ID 分开审核。每个 ID 至少在一条联动命令中出现一次。

## 多设备协同定义

本设计中的“多设备协同”包含电器设备和普通可操作物体，准确含义是“一条场景命令同时调用两个及以上对象操作／任务”。非电器对象不被描述为联网设备，而被描述为机器人协调操作对象。

每条有效联动命令必须：

- 涉及 3–8 个对象；
- 至少跨两个任务类别；
- 具有明确生活场景与共同目标；
- 区分顺序、并行和条件执行；
- 不组合缺少生活逻辑的对象；
- 对炉灶、刀具、烤箱、医疗辅助和安防操作增加安全检查。

预计生成 45–60 条联动命令。最终数量由满足 205 个对象全覆盖所需的最少合理场景决定，不为了固定数量拆分或合并场景。

## 场景编排

联动命令按真实生活活动组织，主要覆盖：

1. 全屋与分区清洁；
2. 烹饪、加热与餐桌准备；
3. 厨房收纳和储物设施开合；
4. 物品递送与生活补给；
5. 衣物清洗、护理和玄关归位；
6. 卧室整理和就寝环境；
7. 工作学习区布置；
8. 卫浴清洁和个人卫生用品归位；
9. 家电管理和节能离家；
10. 安防巡检和应急准备；
11. 老人健康辅助；
12. 娱乐和休闲环境；
13. 室内安装与布置；
14. 垃圾分类、回收和设备维护。

关键设备允许出现在多条命令中，但覆盖审核按唯一对象 ID 计算。

## 工作簿结构

### 工作表一：多设备联动命令表

每行是一条完整自然语言联动命令。字段包括：

- 联动编号：`MDC-001` 起连续编号；
- 场景类别；
- 场景名称；
- 多设备协调命令；
- 涉及任务数；
- 涉及物体数；
- 原有物体 ID；
- VLA 对象名称及 ID；
- 执行阶段摘要；
- 执行方式：顺序、并行、条件；
- 环境或状态触发条件；
- 安全与冲突规则；
- 预期总体输出；
- 合格判定标准；
- 审核状态；
- 审核意见。

命令使用自然、可输入的中文，不采用对象 ID 堆砌。例如：“完成浴室清洁并补齐洗漱用品：先检查地面和水槽材质，清洁镜面、水槽及浴室地面，再把牙刷和牙膏分别放入对应漱口杯，补充皂液器并复核干湿区安全。”

### 工作表二：逐物体动作解析测试表

每个审核对象至少一行，一条命令中的多个对象按行展开。核心表头参照用户截图，保留“测试场景工况”“测试操作步骤”“预期输出结果”，并增加可追踪字段：

- 联动编号；
- 场景类别；
- 测试场景工况；
- 测试操作步骤；
- 预期输出结果；
- 物体来源：原有目录或 VLA；
- 任务类别；
- 物体 ID；
- 中文名称；
- 子任务指令；
- 识别操作；
- 原动作序列；
- 新增细分动作序列；
- 前置条件；
- 细分控制参数；
- 执行阶段；
- 执行模式；
- 依赖物体；
- 目标状态；
- 冲突规则；
- 合格判定；
- 审核状态；
- 审核意见。

测试操作步骤使用统一测试写法：下发联动命令，执行对应物体子任务，生成原动作和额外细分动作，检查依赖与冲突，并形成可审核输出。

预期输出结果必须明确列出：识别任务、物体 ID、识别操作、原动作序列、额外细分动作序列、执行阶段、目标状态和“完成情况：通过”的判定条件。

## 原动作与细分动作关系

两类动作必须分列保存：

- “原动作序列”保持项目当前标准动作或 VLA 基础模板，不被改写；
- “新增细分动作序列”是额外输出，不合并进原动作序列；
- VLA 82 个对象优先直接采用 `meta/vla_82_detailed_action_sequences.json` 中已审核的细分动作；
- 原有 123 个对象根据现有任务、操作计划、物体材质、目标状态和安全要求生成新的细分动作解析。

每个对象通常提供 4–8 个细分步骤。步骤数量服从实际操作复杂度，不机械补足。

## 细分动作规则

### 清洁

包含材质或表面识别、污染检查、工具和清洁剂选择、清扫／擦拭路径、力度或湿度控制、边角覆盖和结果复核。

### 烹饪与加热

包含食材和器具检查、清洗切配顺序、预热、火候档位、时间、调味步骤、防烫和关火／断电检查。

### 整理与摆放

包含分类规则、目标区域确认、拿取顺序、朝向、间距、承重和稳定性检查。

### 家电与门窗

包含当前状态检查、开关或开合动作、参数设置、运行确认、互斥目标检查和异常处理。

### 安防与医疗辅助

包含设备完整性、读数或状态阈值、操作前安全检查、异常判定、提醒或上报，不宣称替代专业医疗或实体执行。

### 递送、取物与安装

包含对象识别、抓取点、搬运姿态、路径与避障、目标位置、释放／固定和稳定性复核。

## 执行阶段与依赖

每条联动命令拆成若干执行阶段：

1. 环境、对象和设备状态检查；
2. 无依赖对象的并行准备；
3. 有前后依赖的核心操作；
4. 收尾、归位和设备关闭；
5. 最终状态与冲突复核。

物体明细中的“执行阶段”和“依赖物体”必须与命令表的阶段摘要一致。依赖示例：使用平底锅前需确认炉灶状态；把牙膏放入杯中前需识别个人漱口杯；清洁地面前先移开地面杂物。

## 冲突与安全规则

至少检查以下冲突：

- 同一设备同时开与关；
- 同一门、抽屉或窗帘同时开与关；
- 同一对象同时被安排到两个目标位置；
- 设备维护时仍处于运行状态；
- 湿式清洁与带电设备操作同时发生；
- 刀具、炉灶或烤箱在无人监控阶段运行；
- 清洁剂与食物、餐具或个人用品发生交叉污染；
- 并行阶段包含显式前后依赖；
- 医疗读数异常但未提醒或上报。

### 工作表三：覆盖审核表

按 205 个对象逐行列出：

- 来源；
- 任务类别；
- 物体 ID；
- 中文名称；
- 对应联动编号；
- 出现次数；
- 是否包含子任务指令；
- 是否包含原动作序列；
- 是否包含细分动作序列；
- 是否包含目标状态；
- 是否完成冲突规则；
- 覆盖状态；
- 审核状态；
- 审核意见。

工作表顶部显示覆盖摘要：原有对象 `123/123`、VLA 对象 `82/82`、总对象 `205/205`。出现次数、覆盖状态和缺失检查采用公式计算，便于用户修改命令后自动复核。

## 表格样式与审核体验

- 使用冻结表头、筛选器、自动换行和适度列宽；
- 场景类别使用一致色标；
- 原有对象和 VLA 对象使用不同底色；
- 顺序、并行和条件执行用不同状态色；
- 未覆盖、缺少动作序列或冲突字段的行以红色标记；
- 审核状态提供“待审核／通过／需修改”三种值，初始统一为“待审核”；
- 不使用合并单元格阻碍筛选，标题区除外；
- 工作簿只交付一个正式 `.xlsx` 文件。

## 验收标准

1. 联动命令数量处于 45–60 条区间，或有清晰理由说明为满足合理场景覆盖而略有调整；
2. 每条命令涉及 3–8 个对象并跨至少两个任务类别；
3. 123 个原有唯一物体和 82 个 VLA 对象全部至少覆盖一次；
4. 逐物体动作解析表至少包含 205 个唯一对象行；
5. 所有对象都有非空原动作序列和独立的新增细分动作序列；
6. VLA 细分动作与已审核目录一致；
7. 原有物体细分动作符合其操作类型、材质和安全约束；
8. 联动命令、明细行和覆盖审核通过联动编号与物体 ID 可相互追踪；
9. 工作簿公式无 `#REF!`、`#VALUE!`、`#DIV/0!`、`#NAME?` 或意外 `#N/A`；
10. 三张工作表均经过视觉渲染检查，无关键文字裁切或不可读区域。

## 范围边界

本次不修改原有动作序列、VLA 审核数据、模型权重、协调器代码或历史测试报告。表格中的联动命令和原有物体细分动作均为待审核设计，只有用户审核确认后才进入项目实现阶段。
