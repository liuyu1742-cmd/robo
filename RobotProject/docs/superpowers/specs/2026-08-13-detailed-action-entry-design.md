# 独立细分动作测试入口设计

## 目标

新建一个可从 PyCharm 直接运行的细分动作测试入口。入口接收口语化中文指令，识别表格审核后的多设备联动场景或单物体操作，只输出必要识别信息、额外细分动作、完成状态和本次运行耗时。

旧入口继续负责原动作序列。所有旧入口均不得返回或显示 `detailed_action_sequence`，细分动作只能从新入口访问。

## 范围

- 覆盖审核表中的 49 个多设备联动场景。
- 覆盖原有 123 个物体和 VLA 82 个物体，共 205 个物体的细分动作。
- 支持口语化表达、物体别名、动作词和场景同义词。
- 低置信度、对象歧义或场景歧义时拒绝猜测，并列出候选项。
- 修复 `evaluate_independent_blind_action_test.py` 默认在 PyCharm 运行时因外部 CSV 指纹不一致而退出的问题。
- 不修改实体设备执行边界；输出仍是软件解析和动作方案。

## 数据源与隔离

新增稳定的细分动作目录，作为新入口的唯一动作数据源。目录由已审核表格对应的目录数据生成，记录：

- 标签 ID 和类型：`coordination_scene` 或 `object_detail`；
- 场景口语命令、场景类别和用途键；
- 任务、物体 ID、中文名和别名；
- 额外细分动作序列；
- 多设备场景涉及的物体、子任务、执行阶段、依赖和冲突规则；
- 训练短语和关键词提示。

新入口不得从原动作序列推导细分动作。旧动作入口不得导入细分动作目录。

## 识别架构

采用“候选约束 + 本地字符级分类模型”的混合识别：

1. 对输入做大小写、空白和常见标点归一化，并识别否定表达。
2. 使用物体别名、场景词和操作词产生候选标签，不直接据此决定结果。
3. 本地字符级模型对口语指令分类，并在候选集合内重新排序。
4. 同时检查最高置信度和前两名差值。
5. 只有满足阈值且不存在明显冲突时才输出动作。
6. 置信度不足、前两名过近、同名物体用途不明确或否定语义冲突时，返回 `clarification_required`，列出最多三个候选，不输出动作序列。

模型标签由 49 个联动场景标签和 205 个物体细分操作标签组成。训练数据使用审核命令、子任务指令、物体别名和受控口语改写生成；训练集、验证集按规范化文本去重，禁止同一句跨集合出现。

## 输出契约

### 单物体细分操作

输出：

- 用户指令；
- 结果类型；
- 识别任务、物体 ID、中文名和操作；
- 模型置信度、识别方式和命中的提示词；
- 额外细分动作序列；
- 完成情况与说明；
- `started_perf_counter_ns`、`ended_perf_counter_ns`、`elapsed_ns`、`elapsed_seconds`。

不得输出原动作序列、动作模板、`final_actions` 或 `expected_actions`。

### 多设备联动

输出：

- 用户指令；
- 识别场景、口语命令和用途；
- 涉及的任务与物体；
- 各物体额外细分动作；
- 执行阶段、依赖、目标状态和冲突检查；
- 完成情况与说明；
- 同一套四个计时字段。

### 歧义结果

输出用户指令、`clarification_required`、拒绝原因、最多三个候选及各自置信度、计时字段；不得输出任何候选的动作序列。

## 计时口径

在用户完成提交后立即调用 `time.perf_counter_ns()`。计时覆盖文本归一化、候选筛选、模型推理、置信度判断、目录查询、动作方案组装和最终结果格式化；在弹窗显示或终端打印前停止。

用户等待输入的时间、结果弹窗停留时间、报告文件写盘时间不计入运行耗时。换算公式为：

`elapsed_seconds = (ended_perf_counter_ns - started_perf_counter_ns) / 1_000_000_000`

## 入口交互

新入口不要求命令行参数即可运行：

- 默认弹出中文输入框；
- 结果使用可滚动文本弹窗展示；
- 图形界面初始化或显示失败时自动回退到终端输入/输出；
- 支持 `--instruction` 便于 PyCharm Run Configuration 和自动测试；
- 支持 `--no-gui`、`--model`、`--catalog`、`--report` 和置信度参数；
- 每次运行写入一个 JSON 报告，内容与屏幕结果一致。

## 旧入口清理

- `manual_instruction_test.py`、`final_demo.py` 及其他现有入口只保留原动作序列语义。
- VLA旧入口仍可识别VLA对象并输出审核前既有动作模板，但删除 `detailed_action_sequence`、额外细分动作文本和对应完成说明。
- 通用结果构造器和格式化器删除细分动作参数及分支。
- 现有批量演示、决策报告等若确实需要细分动作，必须改为显式调用新细分入口服务，不能通过旧结果字段旁路访问。

## 冻结盲测入口修复

当前 `datasets/instruction_blind_paraphrase_template_414.csv` 的 414 条 `human_instruction` 均为空，SHA-256 与冻结包记录值不同；冻结 JSON 内则有完整指令和隐藏答案。因此不能更新指纹或关闭校验来迁就空模板。

修复方式：

- PyCharm 默认运行时只加载冻结 JSON，并执行其结构、关系集合、样本数和内部审计校验。
- `--source-csv` 改为可选参数；只有用户显式提供该参数时才校验外部 CSV 的 SHA-256。
- 显式提供错误 CSV 时仍必须失败，且错误信息同时显示期望值、实际值和文件路径。
- 保留现有隐藏答案在预测之后才用于评分的输入隔离策略。

## 错误处理

- 模型或目录缺失：清晰提示缺失路径和训练命令，不回退到原动作入口。
- 输入为空：提示重新输入，不生成报告动作。
- 未识别或歧义：返回候选，不输出动作。
- 目录覆盖不完整、重复标签、细分动作为空或联动对象冲突：启动时拒绝运行。
- 模型标签与目录标签不一致：启动时拒绝运行，避免旧模型静默误判。

## 测试与验收

自动测试至少覆盖：

- 49 个联动场景和 205 个物体标签完整、唯一；
- 口语化改写可识别，早餐不匹配书籍，地面命令必须涉及地面；
- “我要睡觉了”只联动空调、电动窗帘和卧室灯；
- 同名物体在用途不明确时要求澄清；
- 低置信度和近似候选不输出动作；
- 新入口所有成功结果只有细分动作，没有原动作字段；
- 所有旧入口结果和文本均不含 `detailed_action_sequence` 或“额外细分动作”；
- 四个计时字段满足差值和单位换算关系，且计时不含 GUI 停留；
- 新入口无参数启动路径可被模拟验证，GUI失败会回退终端；
- 盲测默认运行不依赖外部CSV，显式错误CSV仍触发指纹失败；
- 相关既有测试和项目编译检查通过。

验收时从项目根目录和模拟 PyCharm 工作目录分别运行新入口与盲测入口，并保存代表性的 JSON 输出作为证据。
