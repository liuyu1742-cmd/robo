# 动作解析失败明细报告设计

## 目标

每次动作解析批量测试结束后，在运行结果目录新增 `failure_details.txt`，专门记录全部未通过用例的可读诊断信息，方便验收、截图和问题排查。

## 内容

文档首先写出失败总数和各失败类型数量，再按失败类型分组。每条失败用例包含：用例ID、输入指令、期望任务/物体/操作/目标、实际任务/物体/操作/目标、标准动作序列、模型实际生成序列、判定差异和原始异常信息。缺失值统一显示“无”，序列按编号逐步展示。

“判定差异”依据该用例的唯一主失败类型生成中文说明，例如任务不一致时同时列明期望任务与实际任务；动作序列不一致时说明任务语义已匹配但动作步骤与标准序列不同；运行环境错误时保留异常原文。

## 输出约束

- 文件编码为 UTF-8。
- 仅记录失败用例，不重复成功用例。
- 按既定失败类型顺序分组，组内保持测试执行顺序。
- 即使没有失败，也生成文档并写明“本次测试没有失败用例”。
- 不改变现有 JSON、JSONL、CSV、日志和汇总统计。

## 验证

自动测试验证文件存在、分组标题、期望/实际字段、标准/生成序列和中文具体原因；再使用最新500条真实结果重新生成并核对失败条数。
