# 自然口语化测试命令生成规则设计

## 目标

重写动作解析测试的口语化命令生成规则，消除机械模板、语句不通和地点—动作冲突。生成结果仍使用固定随机种子复现，覆盖旧项目操作和82项VLA操作，不修改视频、任务标签、物体标签、标准动作序列或VLA数据表。

## 核心原则

1. 不再生成“按……方式操作……”或“具体是……”等把表格标签直接塞进句子的表达。
2. 地点不能从全局列表随机拼接；地点必须来自物体合理存放位置、动作执行位置或原操作标签中的真实路径。
3. 区分“物体来源”和“动作执行位置”。例如“卧室里的羊毛衫”表示来源，完整命令应为“把卧室里的羊毛衫拿到洗衣机里洗一下”，不能写成“在卧室里清洗羊毛衫”。
4. 不需要地点才能表达清楚的指令不强行添加地点，例如“帮我把窗户关上”。
5. 输入只描述用户目标，不暴露任务类别、测试来源、模板ID、标准动作序列或“口语变体”等测试信息。

## 旧项目命令

旧项目命令改为任务感知模板：

- 洗衣：来源位置 + 搬到洗衣机 + 清洗，例如“把卧室衣柜里的羊毛衫拿到洗衣机里洗一下”。
- 卧室整理：使用床、床边、衣柜等合理位置，例如“把床上的被子叠整齐”。
- 清洁：地面物体可使用客厅/走廊地面；餐具使用水槽；卫浴物体使用卫生间；其余直接说“把……清洁一下”。
- 烹饪：使用厨房、灶台、台面，不使用卧室、书房或门口作为执行位置。
- 家电、安全、门窗、维护和娱乐：只有在位置确实有助于表达时才添加合理地点，否则使用直接请求。
- 取物和递送：明确来源与目标人物/区域，避免把来源写成执行动作的位置。

## VLA命令

VLA操作标签先转换为自然目标句，再生成口语变体：

- `台面→橱柜`：转换为“把台面上的物体收进橱柜”。
- `橱柜→台面`：转换为“把橱柜里的物体拿到台面上”。
- `关闭烤箱门`：转换为“把烤箱门关好”。
- `洋葱切丁：水槽→砧板→碗，刀具与砧板回放水槽`：转换为“用指定刀具把洋葱切成丁，切好放进碗里，刀和砧板用完放回水槽”。
- 复杂多物体操作使用对象专属自然模板，不能把原始标签原封不动拼接到输入中。

同一VLA关系允许用请求词、数量词和自然语序生成多个版本，但不得改变原操作的物体、来源、目的地和动作含义。

## 内部自动检查

每条候选命令进入测试集前执行内部检查。不合格句子直接丢弃并重新生成，不展示给用户。

### 禁止句式

- 包含“按……方式操作”或“按照……方式”。
- 包含“具体是”“需要：”“场景中”“口语变体”“第几种说法”。
- 直接复制标准基准指令或标准动作序列。

### 地点—动作冲突

- 卧室、书房、客厅等位置不得被写成洗衣、洗餐具或烹饪的执行地点；它们可以是物体来源，但句子必须明确移动到洗衣机、水槽或厨房。
- 被子、床垫、枕头等卧室用品不得位于桌面、厨房或门口。
- 洗衣机、烤箱、炉灶等固定设备不得随机出现在不合理房间。
- 箭头路径包含来源和目的地时，生成句必须同时保留两者，不能用随机地点覆盖。

### 质量闭环

- 固定种子 `20260813` 生成500条时，所有命令唯一。
- 禁用句式计数必须为0。
- 地点—动作冲突计数必须为0。
- 旧项目15类任务和VLA 10类任务继续覆盖。
- 纯语义解析匹配率保持在90%以上。
- 完成自动测试后重新运行真实500条完整链路并输出新的结果目录。

## 界面和日志

图形页面继续只显示最终合格的口语化命令，不显示内部检查状态，也不标注旧项目或VLA来源。现有七类结果文件保持不变，包括失败明细文档。
