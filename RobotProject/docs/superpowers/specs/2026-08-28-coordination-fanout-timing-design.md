# 多设备联动全量子操作调用与计时设计

## 目标

修正随机口语测试入口中“多设备联动平均耗时”的语义。联动用例不再只测一次场景分类，而是在场景识别成功后，对场景目录中的全部物体逐一执行独立 BGE 解析调用。联动总耗时必须包含父场景解析和全部子操作解析，因此代表真实的联动规划调用成本。

## 预热与计时边界

模型初始化完成后、正式用例开始前执行一次不计入结果的预热。预热至少覆盖一次张量前向计算；其命令和输出不写入正式结果，避免第一条独立物体用例独自承担 CUDA/CPU 首次执行成本。

独立物体用例继续使用：

`独立总耗时 = 一次 DetailedActionParser.resolve()`

多设备联动用例使用：

`联动总耗时 = 父场景 resolve() + 场景内全部物体的独立 resolve()`

命令生成、模型初始化、预热、界面刷新和证据文件写入均不计入正式用例耗时。

## 子操作调用

父场景解析成功后，读取其真实返回结果中的 `objects`。每个物体通过 `object_label` 查找正式目录项，并使用运行时组合语法生成一条与该物体任务兼容的独立口语命令；不得读取 train、dev 或冻结独立测试集文本。

场景中的每个物体都必须调用一次相同的关键词增强 BGE 入口，不能只固定调用前两个。目录或结果若少于两个物体，该联动用例判为失败。子命令使用父用例随机种子和稳定索引派生，确保同一批次可复现。

每个子调用记录：

- 子操作序号；
- 独立口语命令；
- 期望物体标签；
- 实际结果类型和标签；
- 是否通过；
- 失败原因；
- 开始/结束性能计数；
- 耗时纳秒、毫秒和秒；
- 返回的具体细分动作。

## 通过判定和失败传播

联动用例只有在以下条件全部满足时通过：

1. 父场景结果类型为 `coordination_detailed_action`；
2. 父场景标签与标准标签一致；
3. 至少包含两个物体；
4. 每个目录物体都完成一次子调用；
5. 每个子调用均返回 `object_detailed_action` 且标签与其期望标签一致。

任一子调用失败时，父场景记录判为未通过，失败类别为“联动子操作失败”，并保存所有已执行子调用的结果；后续子对象仍继续执行，确保报告给出完整失败分布。父场景本身失败时不调用子操作。

## 数据结构与汇总

每条结果新增：

- `scene_parse_elapsed_ns/ms`：父场景解析耗时；
- `child_operation_count`：实际子调用数；
- `child_operation_total_elapsed_ns/ms`：全部子调用耗时之和；
- `child_operations`：逐个子调用证据；
- 原 `elapsed_ns/ms`：独立用例为单次调用，多设备用例为父场景加全部子调用的总耗时。

汇总新增：

- 多设备父场景解析平均耗时；
- 多设备每次子操作平均耗时；
- 多设备全部子操作平均总耗时；
- 多设备完整联动平均总耗时。

界面原“联动平均耗时”改名为“联动总平均耗时”，并增加“场景解析平均耗时”“子操作平均耗时”。点击联动记录时，上方细分动作区域按子操作展示命令、物体、耗时与具体动作。

## 输出兼容

JSONL 和 summary JSON 保存完整嵌套字段。CSV 增加父场景耗时、子操作数量、子操作总耗时和压平后的子操作摘要列。Markdown 报告更新计时说明和四项联动指标。既有字段不删除，以保持旧消费者兼容。

## 测试与验收

使用伪解析器和可控时钟先验证：

- 父场景一次加 N 个物体恰好产生 N 次子调用；
- 联动总耗时等于父调用与所有子调用之和；
- 独立用例仍只调用一次；
- 子调用失败会传播到父结果且保留全部证据；
- 少于两个物体时联动失败；
- 预热发生在正式计时前且不进入结果；
- 汇总平均值和 CSV/JSON 字段正确。

随后运行 CUDA 真实随机批次，确认联动记录确实含多个子调用，且展示的联动总平均耗时使用完整总耗时，不再与单次场景分类耗时混淆。由于不同指令和硬件存在波动，不用代码伪造“联动一定更慢”；通过真实的 N+1 次调用和预热后的统计自然体现成本。
