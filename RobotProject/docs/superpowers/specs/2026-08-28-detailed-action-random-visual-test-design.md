# 细分动作随机口语可视化测试入口设计

## 目标

新增一个与旧动作解析入口隔离的可视化测试程序，批量验证 `DetailedActionParser` 对独立物体细分操作和多设备协同场景的口语化命令识别能力。测试条数由用户输入，命令在运行时动态组合，不从 train、dev、独立测试集或既有命令样本中抽取。

验收目标是完整批次总体准确率严格大于 80%。界面必须如实展示未通过用例，不得通过丢弃、重试或只保留成功样本提高准确率。

## 入口与隔离

- 新入口：`detailed_action_random_visual_test.py`。
- 现有 `action_parser_500case_demo.py` 仅作为界面布局参考，不改变其行为。
- 新入口只调用 `tools.detailed_action_runtime.DetailedActionParser`，不把细分动作重新暴露给旧入口。
- 默认使用项目当前正式 BGE 检查点和本地编码器。

## 运行时命令生成

生成器从正式细分动作目录读取结构化事实：标签、入口类型、物体中文名、任务、场景所含物体和允许操作。它不得读取训练、开发、独立测试 split 的文本字段，也不得以目录中的正式场景命令作为测试命令直接输出。

每条命令通过运行时语法槽组合产生：请求前缀、动作表达、物体表达、目标或状态表达、语气后缀和可选口语省略。独立物体用例由物体及其合法操作构造；多设备用例由场景语义提示与设备组合构造。随机种子控制组合顺序和措辞，使同一参数可复现、不同种子可生成不同批次。

每条生成记录同时携带唯一标准标签和类型，因此无需从模型输出反推标准答案。批次生成时确保命令文本不重复；若组合空间不足则明确报错，不静默减少条数。

## 判定规则

- 解析结果为 `object_detailed_action` 时，标准标签与实际标签一致才算独立物体用例通过。
- 解析结果为 `coordination_detailed_action` 时，标准场景标签与实际场景标签一致才算多设备用例通过。
- clarification、异常、类型不符或标签不符均判为未通过。
- 细分动作来自匹配后的正式目录项，用于结果展示和审计，不另行构造虚假标准答案。

运行时采用 BGE 主分类与安全受控的关键词救援。关键词救援仅在命令同时含有明确物体名和与目录任务兼容的动作词、且 BGE 返回低置信度或动作证据不足时启用；否定、问句、已完成陈述、实例歧义、属性不兼容和越界请求均不可被救援。逐条结果记录实际采用的解析路径。

## 计时口径

使用 `time.perf_counter_ns()` 包围单次 `parser.resolve(instruction)`。命令生成、模型初始化、界面更新和文件写入不计入单条解析耗时。

每条结果保存开始计数、结束计数、耗时纳秒、毫秒和秒。汇总分别计算：

- 独立物体平均解析耗时；
- 多设备联动平均解析耗时；
- 全部用例平均解析耗时；
- 全部解析耗时总和。

## 图形界面

Tkinter 界面参考现有 500-case 演示，包含：

- 测试数量、随机种子、运行设备、检查点、编码器和结果目录；
- 生成预览、开始测试、完成当前用例后停止、打开结果目录；
- 当前命令、期望类型/标签、实际类型/标签、细分动作、单条耗时；
- 已完成、通过、未通过、总体准确率、达标状态；
- 独立物体平均耗时、多设备联动平均耗时、总体平均耗时；
- 可按全部、通过、未通过、独立物体、多设备联动筛选的逐条结果表。

后台线程执行模型推理，主线程通过事件队列刷新界面，避免窗口卡死。

## 结果证据

每次运行创建独立时间戳目录并保存：

- `generated_cases.json`：本次现场生成命令及标准标签；
- `results.jsonl`：逐条原始结果与精确计时；
- `results.csv`：便于表格查看；
- `summary.json`：分类计数、准确率、平均耗时和是否超过 80%；
- `report.md`：中文可读测试报告。

## 测试策略

先测试纯逻辑，再接界面：

1. 生成器不访问 split 文件、同种子可复现、命令唯一且标准标签存在；
2. 独立物体与多设备用例均能生成，且不是目录正式命令的原样复制；
3. runner 精确记录每条耗时并正确计算两个分类平均值；
4. clarification、类型不符和标签不符均正确计为失败；
5. CLI 小批次烟雾测试能输出完整证据文件；
6. 正式随机批次的总体准确率严格大于 80%。
