# 随机口语测试结果检查界面调整设计

## 目标

改进 `detailed_action_random_visual_test.py` 的结果检查体验：移除可视化界面的验收字样，汇总未通过原因的数量，并使用户点击任意测试记录时能在上方查看该记录的完整详情。

## 汇总区

- 删除“验收”卡片，不显示“达标”或“未达标”。
- 保留已完成、通过、未通过、总体准确率、实际设备以及三项平均耗时。
- 在指标卡片下新增“失败原因统计”区域。
- 失败原因以中文类别和数量显示，例如：`标签不匹配 8 条｜执行门控未通过 6 条｜对象操作不兼容 5 条`。
- 没有失败记录时显示“无”。
- 统计随测试逐条更新，并在批次完成时使用最终结果重新计算，避免事件重复造成计数偏差。

## 单条详情

结果表中的每个可见行使用稳定的 Treeview 行标识绑定其完整结果对象，不依赖当前显示序号，也不从标签重新生成结果。

点击任意行后，上方实时执行区域切换为该条记录：

- 当前口语命令：显示完整命令；
- 期望类型/标签：显示该条标准答案；
- 实际类型/标签：显示真实解析类型、标签和解析路径；
- 本条耗时：显示该条 `resolve()` 耗时；
- 通过记录：细分动作区域显示该条真实输出的完整细分动作；
- 未通过记录：新增失败原因区域显示具体原因。若失败记录仍包含候选细分动作，动作区域显示并注明“非最终采用”；否则显示“未输出细分动作”。

实时执行时仍自动展示最新结果；用户点击历史记录后则以选中记录为准。筛选表格后重新建立可见行映射，确保点击不会对应到其他记录。

## 失败原因归类

优先展示解析器的具体 `clarification_reason`；没有该字段时使用批次判定的 `failure_reason`；异常则显示 `error`。

界面中文类别至少包括：

- 标签不匹配；
- 结果类型不匹配；
- 解析器异常；
- 执行门控未通过；
- 对象与操作或用途不兼容；
- 对象信息或位置不足；
- 其他需要澄清。

具体原因文本保留在单条详情中，汇总区只显示归类名称和数量。

## 数据与兼容性

- 不改变命令生成、BGE/关键词解析、计时和准确率计算逻辑。
- `summary.json` 中现有 acceptance 数据继续保留，供自动化验收和历史报告使用。
- CSV、JSONL 和 Markdown 证据格式保持兼容；仅可视化界面移除验收卡片与达标字样。
- 旧入口不受影响。

## 测试

新增纯逻辑测试覆盖：失败原因归类、汇总文本、无失败状态、行标识到完整结果的稳定映射。界面事件测试覆盖：选择通过行后显示完整动作；选择失败行后显示具体原因；筛选后选择仍映射正确；界面定义中不再包含“验收”卡片。
